## 2024-05-26 - Semantic Button Conversion with Structural Preservation
**Learning:** When converting non-semantic interactive elements (like `div` or `svg`) to semantic `<button>` elements in this application, it's critical to migrate the exact class names (like `.header-icon`, `.overflow-btn`, `.card-icon`) directly to the new `<button>` wrappers. This repo relies heavily on structural DOM selectors (e.g., `.header-icon:last-child`) in `app/src/ui/menu.ts` and element-specific attributes (like `data-action` or `onclick`) for event delegation. Failing to migrate these properly breaks core interactivity. To prevent visual regressions, the new button wrappers require an inline CSS reset (`background: transparent; border: none; color: inherit; padding: 0; display: inline-flex; align-items: center; justify-content: center;`) while ensuring child `<svg>` elements are sized relatively (`width: 100%; height: 100%;`).
**Action:** Before converting a generic interactive element to a semantic `<button>`, always search the codebase (using `grep`) for how that element is selected for event binding (e.g., structural pseudo-classes, `data-*` attributes). Ensure all such selectors and attributes are carefully migrated to the new `<button>` wrapper.
