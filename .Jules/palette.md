## 2026-04-23 - Adding ARIA Labels to Interactive UI Elements
**Learning:** Found multiple instances where non-semantic structural `<div>` and `<svg>` elements were used as interactive buttons without screen reader context. Replacing them with `<button>` allows default keyboard focus order and pressing "Enter" / "Space" to fire the interaction out-of-the-box, but doing so requires applying a strong CSS reset (`background: transparent; border: none; padding: 0; color: inherit; ...`) along with ensuring internal `<svg>` bounds are forced to `width: 100%; height: 100%;` to perfectly preserve visual layout alignment while upgrading semantic meaning.
**Action:** Always favor `<button aria-label="...">` for interactive icon controls. Whenever migrating structural wrappers in this app to semantic buttons, use the established CSS reset pattern immediately to avoid breaking layout geometries.
