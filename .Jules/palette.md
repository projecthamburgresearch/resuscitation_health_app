
## 2024-05-23 - Replacing structurally identical interactive divs/svgs with semantic buttons
**Learning:** In this application, components like header icons (`.header-icon`) and the overflow menu (`.overflow-btn`) were implemented using non-semantic `<div>` and `<svg>` tags with click listeners attached directly. While visually functioning as buttons, they lacked keyboard operability (tabbing, enter/space interaction) and screen reader identification (`role="button"` and accessible names). Replacing these with semantic `<button>` elements equipped with `aria-label`s significantly improves accessibility while preserving exactly the same layout/hit targets via CSS resets (`background: transparent; border: none; color: inherit; padding: 0; display: inline-flex; align-items: center; justify-content: center;`). Additionally, event delegation scripts target these via structural pseudo-classes (e.g. `.header-icon:last-child`), meaning structural parity and class names must be maintained to avoid breaking the UI.
**Action:** Always favor native `<button>` tags over non-semantic elements for purely interactive UI actions. Apply generic CSS button resets to maintain the visual intent and use `aria-label` to give the button a robust accessible name. Ensure structural relationships and class names match expected JavaScript delegation logic when migrating elements.
