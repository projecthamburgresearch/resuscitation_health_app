   transition — continuing to update it to the finger position was fighting the animation.                                                                                                                      
                                                                                                                                                                                                                
  Fix 2 — Decision tap-to-select then drag-to-confirm: Added state.decisionTapped flag that tracks explicit option selection:                                                                                   
  - Arrive at decision → both options dimmed (no pre-selection)                                                                                                                                                 
  - Tap an option → it highlights, decisionTapped = true, preview stack appears
  - Forward wheel drag → confirms and advances (only if tapped)
  - Card drag down 60px → also confirms (only if tapped)

 Framework Decision: Vite + vanilla TypeScript

 Why not Next.js? Next.js is server-side rendering focused. This is a client-only offline-first PWA. No server needed.

 Why not React? The wheel physics are imperative (touch tracking, angle math, CSS class toggling). React's virtual DOM reconciliation could cause jitter. The previous React attempt
 (prototype/previous-iterations/js-1/) was abandoned.

 Why Vite + vanilla TS?
 - TypeScript adds safety for the complex state machine without framework overhead
 - Vite gives hot reload, bundling, and vite-plugin-pwa for service worker generation
 - ES modules give clean code splitting without a framework
 - CSS can live in separate files with design tokens
 - The wheel physics code ports directly (same imperative style)
 - No learning curve — reads like the current JS but with types

 Checklist Card (moves from footer to middle zone):
 - When a card has checklist items, a "checklist card" is inserted as the next navigable step
 - The checklist card renders checkboxes/toggles in the middle zone (same card styling)
 - User must check required items before advancing (or can skip with forward drag)
 - Algorithm JSON unchanged — checklist data stays on the parent card, renderer creates the card view

 Card Swipe-to-Navigate (drag between zones):

 The three zones are now interactive — you grab cards from the future or pull them back from the past:

 ┌──────────────────────────────────────────────────┬─────────────────┬───────────────────────────────────────────────────┐
 │                     Gesture                      │    Direction    │                      Result                       │
 ├──────────────────────────────────────────────────┼─────────────────┼───────────────────────────────────────────────────┤
 │ Drag preview card (top zone) down into middle    │ Top → Middle    │ ADVANCE to that card                              │
 ├──────────────────────────────────────────────────┼─────────────────┼───────────────────────────────────────────────────┤
 │ Drag history card (bottom zone) up into middle   │ Bottom → Middle │ REWIND to that card                               │
 ├──────────────────────────────────────────────────┼─────────────────┼───────────────────────────────────────────────────┤
 │ Drag decision option (top zone) down into middle │ Top → Middle    │ CONFIRM decision (existing behavior, generalized) │
 └──────────────────────────────────────────────────┴─────────────────┴───────────────────────────────────────────────────┘

 How it works:
 - touchstart on a preview card or history card begins the drag
 - Card follows finger with slight perspective tilt (rotateX proportional to dy)
 - Cross the zone boundary threshold (~40% of zone height) = commit the navigation
 - Release before threshold = card snaps back to its zone (rubber-band)
 - Knob syncs automatically — smooth CSS transition to new anchor position
 - Haptic feedback on commit (15ms vibrate)

 Decision cards already use drag-down-to-confirm — this is the same pattern generalized. On decision cards, preview zone shows the two options; dragging an option down confirms it (no change from REQ-008).

 Knob remains the primary nav — swiping cards is the secondary, more visual method. Both produce the same advance()/rewind() calls and stay perfectly in sync.

 Verification: Drag preview cards down to advance through full algorithm. Drag history cards up to rewind. Knob follows smoothly. Decisions still require tap + drag-down confirm. Rubber-band snap on
