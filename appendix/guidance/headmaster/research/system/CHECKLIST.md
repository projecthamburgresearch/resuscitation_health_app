# Headmaster Checklist (Resuscitation Health App)

Before a Headmaster ticket can be considered complete:

1. current-state claims were verified from project sources, not guessed
2. source pack was explicitly recorded
3. broad intent was converted into a bounded ticket objective
4. bridge-work versus end-state architecture was named explicitly
5. Switchboard/Exit implications were considered when relevant
6. Warden acceptance gates were specified if the outcome is `READY_FOR_WARDEN`
7. destructive changes were named explicitly if a future handoff might move or retire files
8. next-step recommendation is clear for a new operator
